# 黑曼波工作台 V2.1.0 功能矩阵

## 本次版本实现

- 账号角色收敛为管理员、拍摄剪辑、商家三种；旧角色启动时做幂等映射。
- 管理员账号仅后台创建；商家和拍摄剪辑通过微信扫码授权自主注册，无需人工审核。
- 微信 OAuth 使用签名 state、一次性 nonce、5 分钟有效期、open id 唯一约束和授权启动限流。
- 商家端发布订单需求、查看自己的订单、发布制作任务、预览/审核/退回视频、登记发布链接。
- 管理员查看所有订单/商家/任务，报价转单并将制作任务分配给拍摄剪辑。
- 拍摄剪辑只看分配给自己的任务，先接单再制作；上传成片，按商家意见替换修改版本。
- 商家订单、项目素材、发布任务、视频预览与审核均在服务端执行 merchant_id / task_id / link_id 隔离。
- 商家点击“确认已发布”后，按 `DELETE_MEDIA_AFTER_MERCHANT_CONFIRMATION=true` 清理当前交付视频的物理文件；数据库中的视频元数据、订单、任务和审核历史保留。历史已发布文件不会在升级时自动删除。
- V2.1 数据库迁移仅增加 nullable 任务分配字段和索引，并映射旧角色/激活非暂停商家；不删除订单、视频或业务记录。
- 主站入口使用完整订单/制作/商家审核工作台，保留原 Logo。

## 仍需用户完成的外部配置

- 微信开放平台企业主体资质认证、网站应用创建和审核。
- 在美国 VPS `.env` 配置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 和回调域。
- ACR 构建并推送 backend/frontend `v2.1.0` 镜像。
- 在服务器现有 Caddy 中将 `test-v2.heimanbo.com` 站点路由切到 V2.1.0 容器。

## 当前不包含

- 微信公众号内网页授权、微信小程序登录、微信支付。
- 自动视频转码、AI 生成、TikTok 发布/采集等外部服务能力。
- 管理员 MFA 与 WAF/分布式风险控制。
