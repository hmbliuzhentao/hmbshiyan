# V2.1.2 业务流程与三入口架构（按手绘图）

本次保留一套 FastAPI、Next.js 和 PostgreSQL，不建立三套数据库，也不复制账号信息。

| 入口 | 定位 | 可访问角色 | 核心职责 |
|---|---|---|---|
| `heimanbo.com` | 管理总后台 | 仅 `admin` | 所有商家、订单/申请、收款、人员、任务分配、视频、审计、统计 |
| `video.heimanbo.com` | 视频端工作台 | `admin`、`producer` | 派单、接单、制作任务、进度及视频 |
| `deliver.heimanbo.com` | 视频交付和审核中心 | `admin`、`producer`、`merchant` | 员工交付成品，商家仅查看自己订单的视频，审核/退回与修改意见 |
| `test-v2.heimanbo.com` | 现有测试入口 | 依原角色权限 | DNS 生效前保留完整角色工作台，便于平滑过渡 |

独立商家后台不再作为第四个系统；商家的订单申请、审核、退回、资料等复用 `deliver.heimanbo.com` 的角色界面。
旧 `merchant.heimanbo.com` 如已公开使用，应先确认现有路由和连接，再按需设置迁移提示或 302 到 `deliver.heimanbo.com`。

## 业务闭环

1. 商家在交付中心提交需求和订单申请；账号可以微信自主注册，也可由管理员在总后台创建。
2. 管理员总后台接收订单申请、分配给拍摄剪辑，统计订单与收款。
3. 拍摄剪辑在视频工作台接单制作，在交付中心上传制作完成的视频。
4. 商家在交付中心看到**仅属于自己订单**的视频，审核通过或退回修改，填写具体意见。
5. 拍摄剪辑看到退回原因并重新上传，保留审核记录，商家再次验收。
6. 商家登记发布后，按现有明确的交付清理策略处理物理文件，保留记录；管理员可以追踪所有状态。

## 管理员权限说明

管理员对业务平台有完整管理权限，不等于可以绕过其他商家数据私密审计或服务器级权限。管理台集中提供：

- 管理总览：商家数量、账号数量、待分配、待审核、退回修改、快速入口。
- 订单管理：订单台账 / 收款和商家申请 / 需求在同一个入口用页内标签切换。
- 任务与交付：查看全部任务，分配制作人员，跟踪上传和商家审核。
- 视频管理：预览、操作和上传记录。
- 商家管理：创建商家、编辑资料、暂停合作、查看商家关联账号。
- 账号权限：创建管理员/拍摄剪辑/商家账号、启用和停用账户。
- 操作记录：访问现有管理员专用 API `/api/system/audit-logs`。

后端只识别三种角色 admin/producer/merchant。各个 host 通过 `current_user` 限制角色，现有 API 仍按商家关联的 merchant_id / 订单归属鉴权；隐藏前端菜单不构成权限。

## DNS、HTTPS 和登录前置条件

`deploy/Caddyfile.v212-domains.example` 是**配置示例**，不是已经上线的 Caddy 配置。上线前先完成：

- 域名 A/AAAA 解析指向美国 VPS 公网 IP；确认 `heimanbo.com` 的现有站点内容是否可迁移。
- 沿用已有 Caddy 容器，按需扩充域名站点块；Caddy 容器与应用容器必须共享 `heimanbo-test_app`（或实际共享网络）。
- 变更 `.env` 中的 ALLOWED_ORIGINS，允许三个业务域名；微信 OAuth 回调域要与已审核的网站应用及 `WECHAT_REDIRECT_URI` 一致。
- `COOKIE_DOMAIN=.heimanbo.com` 支持子域共享会话，登录身份仍由后端检查角色，商家数据不可越权。
- 如主域名 `heimanbo.com` 暂时无法切换，可以先沿用 `test-v2.heimanbo.com` 上线新界面，再逐个开通子域。

不自动改 DNS/Caddy、不删除旧站点、不清空数据库和视频。务必分别验证管理员、拍摄剪辑、两个不同商家账号在三个入口的权限边界。
