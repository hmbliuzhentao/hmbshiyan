# V2.0 功能矩阵与当前交付状态

本包是 V2.0 第一阶段开发基线，不代表所有外部服务已经开通，也不代表已经部署到 ECS。

## 本次代码已落地
- 四个独立面板域名：work / video / merchant / system，使用同一前后端服务按域名显示独立导航。
- 统一认证入口 auth 子域名。
- 邮箱或手机号 + 密码登录。
- 商家自助注册申请（邮箱/短信 OTP 验证；商家状态为 pending）。
- 忘记密码 OTP 重置。
- 微信开放平台网站扫码登录 OAuth 回调框架。
- 微信账号绑定 / 解绑基础接口。
- 登录会话查看与单会话撤销。
- 修改密码、绑定邮箱/手机号接口。
- 用户角色与面板域名访问限制。
- 通用产品、脚本、分镜、提示词、素材资料 API。
- 审计日志和系统总览接口。
- 保留 V1.5 原页面在 `/legacy-v15`，保留原有订单、商家项目、发布任务接口。
- 商家 workspace 资料按 merchant_id 过滤，后端查询不依赖前端隐藏。

## 仍需真实服务商配置 / 后续开发
- 邮箱 OTP：需要真实 SMTP 服务器账号。
- 短信 OTP：当前提供通用 HTTP 网关适配器，需按选定短信服务商 API 对接并配置模板。
- 微信扫码：需要微信开放平台网站应用审核通过，并配置 AppID、AppSecret、回调域。
- 微信公众号内网页授权与微信小程序登录不是本次扫码 OAuth 的同一能力，需单独开发。
- 产品图片/原始素材的大文件对象存储直传（建议 OSS / S3）。
- 完整视频剪辑、转码、AI 生成、自动封面、TikTok 数据采集等需要独立服务/API，不会仅靠管理后台代码自动获得。
- 订单、视频任务、交付清理、统计的 V2 专属体验和回归测试仍需分阶段补齐。
- 多因素 TOTP、管理员强制 MFA、邀请链接、设备风险策略、验证码供应商签名校验需进入第二阶段安全开发。
- V1.5 数据迁移需先在副本上演练，不可直接将 V2.0 指向 V1.5 数据库。

## 角色
- super_admin：超级管理员
- admin：系统管理员
- manager：内部管理
- producer：视频制作
- editor：剪辑
- viewer：内部只读/运营
- merchant：商家

面板域名的服务端访问控制与业务 API 的权限检查是两层控制；前端菜单隐藏不构成安全边界。
